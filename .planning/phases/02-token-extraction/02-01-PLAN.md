Create a Python extraction pipeline with this structure:

```
scripts/
  extract-tokens.py      # Main orchestrator
  lib/
    __init__.py           # Package init
    scss_resolver.py      # SCSS expression computation
    dtcg_formatter.py     # Audit data -> DTCG structure transformation
```

**scripts/lib/scss_resolver.py:**
- Function `resolve_scss_expression(expression, variable_context)` that handles:
  - Color functions: darken(), lighten(), mix(), rgba(), hsla() -- use pyScss Compiler
  - Arithmetic: `$base*0.78`, `$spacer*1.5` -- evaluate with variable substitution
  - Variable references: `$primary` -> look up in variable_context
  - Literal values: return as-is (hex colors, plain numbers, rem/px values)
- Function `build_variable_context(audit_data)` that loads all 465 SCSS variables from theme-audit.json into a dict for expression resolution
- Handle resolution failures gracefully: log warning, return original expression as fallback
- Round computed dimension values to 4 decimal places to avoid floating point drift

**scripts/lib/dtcg_formatter.py:**
- Function `format_core_tokens(audit_data, resolver)` that:
  - Groups SCSS variables by category (color, spacing, typography, borderRadius, shadow, transition)
  - Skips category "other" (non-design values like $prefix)
  - For colors: extract v8 CSS custom properties from rootBlock=='v8-theme' as full palettes (100-900 shades), plus SCSS color variables
  - For spacing: extract spacer variables, use zero-padded numeric naming (025, 050, 100, 200)
  - For typography: extract font-family, font-size, font-weight, line-height tokens. fontWeight values MUST be numbers not strings
  - For borderRadius: extract radius variables with sm/md/lg naming
  - For shadow: convert CSS box-shadow strings to DTCG object format {color, offsetX, offsetY, blur, spread}
  - For transition/duration: extract timing values
  - Sets $type at group level using type inheritance (not on every token)
  - Builds $description with: source file + line, original expression (if differs from computed), Bootstrap override note (if isBootstrapOverride), usage count
  - Wraps everything under top-level "ff" group
  - V8 design system values take precedence over legacy where conflicts exist
  - Active legacy values (Bootstrap semantics) included with $description noting legacy origin

- Function `format_semantic_tokens(audit_data, core_tokens)` that:
  - Creates semantic tokens referencing core tokens using {ff.group.token} syntax
  - Maps CSS custom properties from rootBlock=='theme' to semantic names
  - Uses Bootstrap semantic names unchanged (primary, secondary, success, danger, etc.)
  - Maps v8 theme properties to semantic purpose-based names (action.primary, background.default, etc.)
  - Validates all references point to actual core token paths before writing
  - Sets $type at group level
  - Builds $description with usage context

- Helper `shadow_css_to_dtcg(css_shadow_string)` to parse "0px 2px 8px rgba(66, 66, 66, 0.07)" into DTCG object format

**scripts/extract-tokens.py:**
- Main orchestrator that:
  1. Loads theme-audit.json from tokens/audit/
  2. Builds SCSS variable context via scss_resolver
  3. Calls dtcg_formatter.format_core_tokens() to produce core token structure
  4. Calls dtcg_formatter.format_semantic_tokens() to produce semantic token structure
  5. Writes tokens/core.json with 2-space indentation
  6. Writes tokens/semantic.json with 2-space indentation
  7. Prints summary: count of tokens per category, total core, total semantic
- Use argparse for optional --audit-path and --output-dir arguments (defaults: tokens/audit/theme-audit.json, tokens/)
- Ensure output is valid JSON before writing (json.dumps with ensure_ascii=False)

**Key constraints from CONTEXT.md decisions:**
- V8 values only, legacy excluded UNLESS actively used (Bootstrap semantics)
- 18 missing component values: document as gaps only, do NOT create tokens
- SCSS function expressions: resolve to final value in $value, preserve original in $description
- Full v8 @each loop palettes: ALL generated values (100-900), not just referenced ones
- $description includes BOTH origin AND usage context

**Use Phase 1 example files as format reference:**
- tokens/audit/example-core.json shows correct core token structure
- tokens/audit/example-semantic.json shows correct semantic reference syntax

**IMPORTANT:** Install required pip packages before running: `pip install pyScss jsonschema jsondiff`
