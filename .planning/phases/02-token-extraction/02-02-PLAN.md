  <action>
Create validation scripts that run three categories of checks:

**scripts/lib/validators.py:**

Function `validate_dtcg_schema(token_data, file_label)`:
- Walk the entire JSON tree recursively
- For every leaf token (object with $value): verify $type exists (explicit or inherited from parent group)
- Verify no reserved characters ($, {, }, .) in object keys (except DTCG $ properties)
- Verify $value is present and non-null on every leaf token
- Verify $description is present on every leaf token (Phase 2 requirement)
- Type-specific format checks:
  - fontWeight: $value must be a number (int), not a string
  - shadow: $value must be an object with keys: color, offsetX, offsetY, blur, spread
  - dimension: $value must be a string containing a unit (rem, px, em, ms, s)
  - color: $value must be a string matching hex (#xxx or #xxxxxx), rgb(), rgba(), or named color
  - fontFamily: $value must be a string
- Return list of errors with token path, issue description

Function `validate_references(core_data, semantic_data)`:
- Extract all $value strings matching pattern `{ff.*}` from semantic_data
- For each reference, resolve the dot-path against core_data
  - e.g., {ff.color.primary-500} -> core_data["ff"]["color"]["primary-500"]
  - Handle hyphenated token names (primary-500 is a single key, not nested)
- Report any unresolvable references with full path
- Check for circular references (reference chains that loop back)
- Return list of unresolved references

Function `check_naming_conventions(token_data, file_label)`:
- Verify all tokens are under "ff" top-level group
- Verify all keys are kebab-case (lowercase letters, numbers, hyphens only)
- Verify no duplicate keys within any group
- Return list of naming violations

Function `count_tokens(token_data)`:
- Walk tree, count leaf tokens (objects with $value)
- Return total count and per-category counts

**scripts/lib/diff_validator.py:**

Function `compare_to_audit(core_path, semantic_path, audit_path)`:
- Load audit data from theme-audit.json
- Load core and semantic token files
- For each SCSS variable in audit that was extracted (category != 'other'):
  - Find corresponding token in core.json
  - Compare $value against audit computedValue (or value if no computedValue)
  - Allow rounding tolerance: dimension values within 0.001 units, colors exact match
- For CSS custom properties in audit:
  - Find corresponding token in core or semantic
  - Compare values
- Report mismatches with: audit variable name, expected value, actual token value
- Report coverage: how many audit variables are represented in tokens vs total extractable
- Return structured report dict

**scripts/validate-tokens.py:**
Main validation orchestrator:
1. Load tokens/core.json and tokens/semantic.json
2. Run DTCG schema validation on both files
3. Run reference validation (semantic references core)
4. Run naming convention checks on both files
5. Run audit diff comparison
6. Print results to console with clear pass/fail per check
7. Write validation-report.json to tokens/ with full results
8. Exit code 0 if all checks pass, 1 if any fail

Use argparse for optional --core, --semantic, --audit paths.
Print a summary table at end:

```
Audit Diff:                   PASS (0 mismatches, 85% coverage)
------------------
OVERALL: PASS
```
