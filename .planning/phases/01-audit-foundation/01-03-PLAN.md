Create a comprehensive specification document that defines every aspect of the token structure Phase 2 will produce. This document is the contract -- Phase 2 implementers read this to know exactly what to create.

Include these sections:

**1. File Structure**
```
tokens/
  core.json     -- Primitive tokens (raw design values)
  semantic.json -- Purpose-based tokens (reference primitives)
```
Per CONTEXT.md decision: two tiers only (core + semantic), one file per tier, tokens/ at project root.

**2. W3C DTCG Format Rules**
Document the format requirements:
- Token properties use `$` prefix: `$value` (required), `$type` (required), `$description` (recommended)
- Groups are plain JSON objects containing tokens or nested groups
- Group properties also use `$` prefix: `$description` for group descriptions
- Token names MUST NOT contain: `$` (reserved for properties), `{` or `}` (reserved for references), `.` (reserved for path separators in references)
- Reference syntax: `{group.subgroup.token}` using dot-separated path inside curly braces
- Valid `$type` values for our categories:
  - Colors: `"color"` (hex, rgb, hsl string values)
  - Spacing/sizing: `"dimension"` (number + unit, e.g., "1rem", "16px")
  - Font family: `"fontFamily"` (string or array of strings)
  - Font weight: `"fontWeight"` (number: 300, 400, 500, 600, 700)
  - Font size: `"dimension"` (same as spacing)
  - Line height: `"number"` (unitless) or `"dimension"` (with unit/percentage)
  - Letter spacing: `"dimension"`
  - Border radius: `"dimension"`
  - Shadow: `"shadow"` (object with color, offsetX, offsetY, blur, spread)
  - Duration/transition: `"duration"` (e.g., "300ms")

**3. Naming Conventions**
Per CONTEXT.md locked decisions:
- **Prefix:** `ff` (formsflow) as top-level group on all tokens
- **Group separator:** Dot notation via JSON nesting (ff > color > primary-500 becomes `{ff.color.primary-500}` in references)
- **Bootstrap-originated names:** Keep familiar names (primary, secondary, success, danger)
- **Color shades:** Numeric scale (ff.color.primary-100 through ff.color.primary-900) for primitive tier
- **Spacing:** T-shirt sizes (ff.spacing.xs, ff.spacing.sm, ff.spacing.md, ff.spacing.lg, ff.spacing.xl) for semantic tier; numeric scale (ff.spacing.025, ff.spacing.050, etc.) for core tier mapping to existing --spacer-* properties
- **Token name format:** kebab-case within groups (e.g., "primary-500", "font-size", "border-default")
- **No reserved characters in names:** Token names must not contain $, {, }, or .

Provide a naming convention table:

| Category | Core Pattern | Semantic Pattern | Example Core | Example Semantic |
|----------|-------------|------------------|--------------|------------------|
| Color | ff.color.[name]-[shade] | ff.color.[purpose].[variant] | ff.color.primary-500 | ff.color.action.primary |
| Spacing | ff.spacing.[number] | ff.spacing.[t-shirt] | ff.spacing.100 | ff.spacing.md |
| Typography | ff.typography.[property].[value] | ff.typography.[role].[property] | ff.typography.font-size.xl | ff.typography.heading.font-size |
| Border Radius | ff.radius.[size] | ff.radius.[purpose] | ff.radius.md | ff.radius.button |
| Shadow | ff.shadow.[size] | ff.shadow.[purpose] | ff.shadow.md | ff.shadow.card |
| Duration | ff.duration.[name] | ff.duration.[purpose] | ff.duration.normal | ff.duration.transition |

**4. Type Inheritance**
Document that `$type` can be set at the group level and inherited by all tokens in that group:
```json
{
  "ff": {
    "color": {
      "$type": "color",
      "primary-500": {
        "$value": "#253DF4",
        "$description": "Primary brand color"
      }
    }
  }
}
```

**5. Shadow Token Format**
The DTCG shadow type requires a specific object structure:
```json
{
  "$value": {
    "color": "#30343608",
    "offsetX": "0px",
    "offsetY": "2px",
    "blur": "4px",
    "spread": "0px"
  },
  "$type": "shadow"
}
```
Document how the existing CSS shadow values (e.g., `0px 2px 4px 0px rgba(48, 52, 54, 0.08)`) map to this structure.

**6. v8 vs Legacy Theme Handling**
Document the decision for Phase 2: The codebase has TWO theme systems (_theme.scss and v8-scss/_theme.scss) with overlapping but different values. The spec should note:
- v8-scss values take precedence (loaded later in index.scss)
- Core tokens should reflect v8-scss values where they differ
- Legacy _theme.scss values documented in audit for reference but not duplicated as tokens

**7. Validation Requirements**
Document what Phase 2 token files must pass:
- Valid JSON
- Every token has `$value` and either explicit `$type` or inherits from parent group
- Every `$value` matches the format for its `$type` (colors are valid hex/rgb, dimensions have units, etc.)
- References use `{path.to.token}` syntax and resolve to existing tokens
- No circular references
- No reserved characters in token names
