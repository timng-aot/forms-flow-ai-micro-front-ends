  <name>Task 1: Scan component micro-frontends for hardcoded design values</name>
  <files>tokens/audit/components-audit.json, tokens/audit/components-audit.md</files>
  <action>
Read all SCSS and CSS files in these 5 component packages:
1. forms-flow-admin/src/ (8 SCSS files found)
2. forms-flow-nav/src/ (4 SCSS files found)
3. forms-flow-review/src/ (1 SCSS file: index.scss)
4. forms-flow-submissions/src/ (2 SCSS files)
5. forms-flow-components/src/ (0 SCSS found -- also check for .css files)

For each file, detect hardcoded design values using these patterns:

**Colors:**
- Hex: #RGB, #RRGGBB, #RRGGBBAA patterns
- RGB/RGBA: rgb(), rgba() function calls
- HSL/HSLA: hsl(), hsla() function calls
- Named colors used as values (not within variable references)
- EXCLUDE: values inside SCSS variable declarations that reference theme variables (e.g., `color: $primary` is NOT hardcoded)
- EXCLUDE: values that are CSS custom property references (e.g., `color: var(--ff-primary)` is NOT hardcoded)

**Spacing/Dimensions:**
- Pixel values used directly: Npx (where contextually a spacing/sizing value)
- Rem values used directly: Nrem
- Em values: Nem
- Percentage values used for spacing (not layout percentages like width: 100%)
- Focus on: padding, margin, gap, top, right, bottom, left properties

**Typography:**
- Font-family declarations not using variables
- Font-size with hardcoded values (not var() references)
- Font-weight with hardcoded numeric values
- Line-height with hardcoded values
- Letter-spacing with hardcoded values

**Border Radius:**
- border-radius with hardcoded pixel/rem values

**Shadows:**
- box-shadow with hardcoded values
- text-shadow with hardcoded values

For each detected value, record:
- The raw value
- Token type category
- Source package
- Source file (relative path)
- Line number
- CSS property it was used on

Then deduplicate: group identical values, count total occurrences, list all locations.

<task type="auto">
  <name>Task 2: Perform gap analysis comparing components against shared theme</name>
  <files>tokens/audit/gap-analysis.json</files>
  <action>
Load tokens/audit/theme-audit.json (from Plan 01) and tokens/audit/components-audit.json (from Task 1). Compare every unique hardcoded value found in components against the theme audit to classify each as:

1. **Exists in theme** - The exact value matches a theme SCSS variable or CSS custom property. Component should use the theme variable instead of hardcoding.
2. **Close match** - A similar value exists in theme (e.g., component uses #4A4A4A, theme has $gray-darkest: #303436 -- close but different gray). May indicate intentional variation or accidental divergence.
3. **Missing from theme** - Value does not exist in shared theme at all. This is a gap -- this value should potentially become a shared token.

For each "missing from theme" value, suggest a token name following the user's naming conventions:
- Prefix: ff
- Colors: ff.color.[semantic-name] (e.g., ff.color.border.default, ff.color.text.muted)
- Spacing: ff.spacing.[t-shirt-size] (map to nearest t-shirt size: xs/sm/md/lg/xl)
- Typography: ff.typography.[property].[size] (e.g., ff.typography.font-size.body)
- Border radius: ff.radius.[size]
- Shadows: ff.shadow.[size]

Output gap-analysis.json:
```json
{
  "metadata": {
    "auditDate": "YYYY-MM-DD",
    "totalComponentValues": N,
    "existsInTheme": N,
    "closeMatch": N,
    "missingFromTheme": N
  },
  "gaps": [
    {
      "value": "#e0e0e0",
      "type": "color",
      "status": "missing",
      "occurrences": 12,
      "sourcePackages": ["forms-flow-admin", "forms-flow-nav"],
      "suggestedToken": "ff.color.border.default",
      "rationale": "Used as border-color across 2 packages, no matching theme variable"
    },
    {
      "value": "#4A4A4A",
      "type": "color",
      "status": "close-match",
      "occurrences": 3,
      "sourcePackages": ["forms-flow-admin"],
      "closestThemeValue": "$gray-darkest (#303436 in _theme.scss, #4A4A4A in v8-scss)",
      "suggestedAction": "Verify intent -- v8-scss uses same value, may already be covered"
    },
    {
      "value": "16px",
      "type": "spacing",
      "status": "exists-in-theme",
      "occurrences": 5,
      "themeVariable": "--spacer-100 (1rem = 16px)",
      "suggestedAction": "Replace hardcoded 16px with var(--spacer-100)"
    }
  ]
}
```

Important considerations:
- When comparing spacing values, normalize units (16px = 1rem at default browser settings)
- For colors, do exact hex comparison (case-insensitive)
- The v8-scss/_theme.scss defines different values than _theme.scss for some variables (e.g., different grays). Check against BOTH sets of values.
- Document which values are candidates for becoming shared tokens vs which are truly one-off component-specific values (based on occurrence count -- values appearing in 2+ packages are strong candidates for shared tokens)
