<task type="auto">
  <name>Task 1: Create Style Dictionary configuration with DTCG validation</name>
  <files>
    tokens/config/style-dictionary.config.js
  </files>
  <action>
    Create tokens/config/style-dictionary.config.js that serves as the single configuration file, parameterized for both core and semantic builds. Use ES module syntax (import/export).

    The configuration must include:

    1. **Token Studio integration:**
       ```javascript
       import StyleDictionary from 'style-dictionary';
       import { register, expandTypesMap } from '@tokens-studio/sd-transforms';
       register(StyleDictionary);
       ```

    2. **Custom --ff- prefix name transform:**
       Register a custom transform named 'name/css/ff-prefix' that converts token paths to CSS variable names with --ff- prefix. Token path ['ff', 'color', 'indigo-100'] becomes 'ff-color-indigo-100' (Style Dictionary adds the -- prefix for css/variables format).

       IMPORTANT: The top-level group in both core.json and semantic.json is "ff". The path will be ['ff', 'color', 'indigo-100']. The CSS variable should be --ff-color-indigo-100. Since css/variables format already prepends --, the transform should return the path joined with hyphens (e.g., 'ff-color-indigo-100') and let the format add the -- prefix. Study how Style Dictionary's css/variables format constructs the variable name to get this right.

    3. **DTCG validation preprocessor:**
       Register a custom preprocessor named 'validate-dtcg' that:
       - Traverses all tokens recursively
       - Checks that leaf tokens (those with $value) have $type (either directly or inherited from a parent group)
       - Checks token names don't contain forbidden characters: {, }, $
       - Validates $type values match DTCG spec: color, dimension, fontFamily, fontWeight, duration, cubicBezier, number, shadow, strokeStyle, border, transition, gradient, typography
       - Throws descriptive error on first violation (fail fast)

    4. **Exported build function:**
       Export a function that accepts parameters:
       - `source`: path to token JSON file (e.g., '../tokens/core.json' or '../tokens/semantic.json')
       - `destination`: output filename (e.g., 'core-tokens.css' or 'semantic-tokens.css')

       The function creates a StyleDictionary instance with:
       - `source: [sourcePath]`
       - `preprocessors: ['tokens-studio', 'validate-dtcg']`
       - `expand: { typesMap: expandTypesMap }` for composite token expansion (shadows, typography)
       - Platform 'css' with:
         - `transformGroup: 'tokens-studio'`
         - Custom transforms array including 'name/css/ff-prefix'
         - `buildPath: 'tokens/dist/'`
         - Single file with `format: 'css/variables'`, `outputReferences: true`, `selector: ':root'`

    5. **CLI entry point:**
       Accept source and destination as command-line arguments so the npm scripts can call:
       ```bash
       node tokens/config/style-dictionary.config.js tokens/core.json core-tokens.css
       node tokens/config/style-dictionary.config.js tokens/semantic.json semantic-tokens.css
       ```

    Per user decision: CSS custom properties only, --ff- prefix, separate files, semantic refs preserved via outputReferences.

    Per user decision: Bidirectional design -- the same config works for code-extracted tokens (now) and Figma-exported tokens (future). The tokens-studio preprocessor normalizes both formats.

    Per user decision: Validation happens in the pipeline (not deferred to Phase 4). The validate-dtcg preprocessor ensures Token Studio importability at build time.

    NOTE on transforms: The 'tokens-studio' transformGroup already includes many transforms. The custom 'name/css/ff-prefix' transform needs to be added carefully. Check whether it needs to replace the default name transform in the group or be appended. If the transformGroup's name transform conflicts, override it by specifying the full transforms list including 'name/css/ff-prefix' instead of the ones from the transformGroup. Consult @tokens-studio/sd-transforms documentation for the exact list of transforms in the 'tokens-studio' transformGroup.
  </action>

    - File contains 'validate-dtcg' preprocessor registration

    - File imports from 'style-dictionary' and '@tokens-studio/sd-transforms'
  </verify>

  </done>

<task type="auto">
  <name>Task 2: Generate CSS outputs and wire npm scripts</name>
  <files>
    tokens/dist/core-tokens.css
    tokens/dist/semantic-tokens.css
    forms-flow-theme/package.json
  </files>
  <action>
    1. Create tokens/dist/ directory if it doesn't exist.

    2. Run the Style Dictionary build for core tokens:
       ```bash
       cd forms-flow-theme && node ../tokens/config/style-dictionary.config.js ../tokens/core.json core-tokens.css
       ```

    3. Run the Style Dictionary build for semantic tokens:
       ```bash
       cd forms-flow-theme && node ../tokens/config/style-dictionary.config.js ../tokens/semantic.json semantic-tokens.css
       ```

       Note: Semantic tokens reference core tokens via {ff.color.*} syntax. With outputReferences: true, these should render as var(--ff-color-*) in the CSS output. For this to work, the semantic build needs to know about core tokens. If references fail to resolve, the semantic config may need to include BOTH core.json and semantic.json as sources, with a filter to only output semantic tokens. Adjust the config accordingly.

    4. Verify core-tokens.css:
       - Contains :root { } block
       - All CSS variables start with --ff-
       - Contains color tokens (e.g., --ff-color-indigo-100)
       - Contains spacing tokens (e.g., --ff-spacing-*)
       - Contains no blend-with-white-to-hex() expressions
       - Values are clean hex colors, dimensions, font families, etc.

    5. Verify semantic-tokens.css:
       - Contains :root { } block
       - All CSS variables start with --ff-
       - Color tokens reference core tokens via var(--ff-color-*)
       - Non-color tokens (shadows, radius) may have direct values if they don't reference core tokens

    6. Add npm scripts to forms-flow-theme/package.json:
       ```json
       "build:tokens:precompute": "node ../tokens/scripts/precompute-colors.js",
       "build:tokens:core": "node ../tokens/config/style-dictionary.config.js ../tokens/core.json core-tokens.css",
       "build:tokens:semantic": "node ../tokens/config/style-dictionary.config.js ../tokens/semantic.json semantic-tokens.css",
       "build:tokens": "npm run build:tokens:precompute && npm run build:tokens:core && npm run build:tokens:semantic"
       ```

    7. Verify the full pipeline by running:
       ```bash
       cd forms-flow-theme && npm run build:tokens
       ```
       This should chain: precompute -> core build -> semantic build without errors.

    8. Verify Token Studio importability: The source JSON files (tokens/core.json and tokens/semantic.json) should be pure W3C DTCG format. Confirm:
       - All tokens have $type and $value
       - No SCSS expressions remain
       - Reference syntax uses {ff.*} curly braces
       - No forbidden characters in token names
       The validate-dtcg preprocessor running during build provides this check. If it passed, tokens are importable.
  </action>
